产品规划方案 · v1.0

科三路线通 · 苏州科技城

一款面向「科目三」备考学员的微信小程序。支持 C1 手动挡 / C2 自动挡切换——把「背路线」从死记硬背，变成选择 + 排序的闯关式训练：按线路考顺序，按车型考难点手法，按场景考灯光操作。

微信小程序 C1 手动 16 项 / C2 自动 15 项 4 条线路 顺序训练 + 难点专项 + 灯光 云开发 / 免服务器 MVP 建议 2 周

01产品定位与目标用户

先回答一个问题：学员到底卡在哪里？
🧠

记不住顺序

练车时全靠教练喊「该超车了」，自己脑子里没有完整流程。

🔀

线路混着记

1 号线和 4 号线有两个版本，项目位置不同，越练越糊。

💡

灯光容易挂

语音一响脑子空白，远近交替 / 雾灯双闪该选哪个反应不过来。

📱

没有随时自测

只能到驾校才能练，碎片时间（通勤、排队）完全浪费。

核心洞察：科目三真正的考点不是「会不会开车」，而是在正确的路段，按正确的顺序，做正确的动作。所以产品的主线交互不该是「看视频/看文章」，而是让学员自己把顺序排出来、把项目选出来——输出式记忆远比输入式有效。

02功能架构

四个模块，一个核心

🧩 路线记忆训练 核心差异化

按线路出题，三种题型由易到难，覆盖「整体顺序 → 单点判断 → 空间位置」三个记忆层次。

  • 顺序排序题：打乱项目卡片，点选排成正确顺序
  • 情境判断题：播报「行驶到 XX」，四选一选操作
  • 地图定位题：在路线图上点出项目发生的路段
  • 跨线路混淆模式：多线混合，专治「练 A 考 B」

⚑ 难点专项 按车型

顺序题练的是记忆，专项练的是手法。针对 C1 / C2 各自的真实失分点，单独成套。

  • 操作步骤排序：起步、加减挡、靠边停车…按正确顺序点出
  • 判断题：油离配合、踏板使用、车速要求等易错认知
  • C1 与 C2 内容不同，跟随车型开关自动切换

💡 灯光模拟考试

两车型完全相同的通用模块。语音念场景，学员在模拟灯控面板上操作，3 秒内判定。

  • 12 组标准夜间场景题库
  • 练习模式：即时讲解为什么
  • 考试模式：连续 5 题，汇总判分
  • 高危题强制复练（雾天 / 故障停车）

🗺️ 路线速查（学习模式）

不考，只用来「学」和「考前过一遍」。是训练模式的知识底座。

  • 线路图 + 可点击项目节点，弹出操作要点
  • 「第一视角」时间轴：像跟车一样逐步播报
  • 每项配一句口诀与扣分点

📊 我的 · 错题与掌握度

让进步看得见，也是留存的关键。

  • 错题本，按线路 / 车型 / 题型分组
  • 4 条线路掌握度进度条（弱项一目了然）
  • 「整场模拟」：抽一条线路从头考到尾

🔍 数据来源可追溯 长期壁垒

每个节点带来源标记（国标 / 实测 / 图上 / 待校准），UI 上用圆点可视化。

  • 学员看得见「哪些是已确认的」
  • 我们一眼筛出待核项，不靠记忆
  • 教练校准后再转为正式数据

03核心题型设计

这是产品的灵魂，也是最该先做对的部分

题型 A · 顺序排序（考整体流程）

屏幕上方是待选池（打乱的项目卡片），下方是答题区。学员按自己记忆的顺序依次点入，点错可移除。提交后逐项标红/标绿，并给出正确顺序对照。

① 选线路1号线 / 2号线 / 4号线① / 4号线②
→
② 打乱卡片从待选池点选，依次放入答题区
→
③ 提交判分逐项对错高亮 + 正确顺序对照
→
④ 错题入本排错的项自动进错题本，次日重推

题型 B · 情境判断（考单点记忆）

模拟真实语音播报，例如：「前方路口请右转」「现在开始百米直线行驶」，四选一选择对应操作。干扰项专门取自同一线路的其他项目，逼学员区分相邻路段。

题型 C · 跨线路混合（考区分能力）★ 杀手锏

同时抛出 2~3 条线路的片段，让学员判断「这一步属于哪条线 / 该线路在这一步做什么」。这是苏州科技城多线路考场最真实的痛点——别人都在做单线记忆，我们做跨线区分，这是天然的差异化壁垒。

题型 D · 难点专项（考手法，不考记忆）★ 按车型分叉

顺序题解决的是「记不记得住」，专项解决的是「手法对不对」。这两件事必须分开练——很多学员路线背得滚瓜烂熟，一上车还是熄火。专项题同样是操作步骤排序与判断题两种形态，但题目内容按车型分叉。

C1 手动挡 · 6 个专项

失分集中在「手脚配合」与「挡位时机」

起步顺序加减挡操作顺序靠边停车顺序 油离配合四挡要求直线行驶

已知痛点：C1 科三失误中 40% 以上源于熄火、脱挡或挡速不匹配；「离合器没松完不能踩油门，油门没松彻底不能碰离合」是反复出错的一条。

C2 自动挡 · 6 个专项

失分转移到「观察预判」与「踏板习惯」

起步顺序靠边停车（P 挡）顺序踏板使用 车速控制超车新规观察与预判

反直觉的一点：自动挡操作更简单，但通过率反而略低（约 81% vs 手动挡 85%）——难点转移到观察、转向灯与点刹这些细节上。这正是产品能讲给 C2 学员的价值。

为什么顺序题是重点：科目三考试全程约 15~20 个考核项，任何一个顺序记错就可能引发连锁错误（比如该掉头的地方没提前变道）。顺序题用「输出」代替「阅读」，记忆留存率显著更高，且天然适合手机碎片时间。

04官方考核项目与线路序列

依据公安部令第 162 号第三十四条 —— C1 手动挡 16 项 / C2 自动挡 15 项，每条线路都是这些项的一个排列
先纠正一个容易搞错的点：科目三道路驾驶技能考试的考核项是国家统一规定的 16 项，不是各考场自定的。 考场之间的差别不在于「考几项」，而在于这 16 项排成什么顺序、在哪个路段做。 所以任何一条线路的考核项数量都应当是 16 项，少于 16 的清单一定是漏了项。

官方 16 项（公安部令第 162 号 · 第三十四条）

项目考场常见播报 / 俗称关键点
1. 上车准备绕车一周逆时针绕车、按感应按钮、调座椅后视镜、系安全带、复位灯光挡位
2. 模拟夜间灯光灯光考试首考项，语音结束后 5 秒内完成，错一次扣 100 分
3. 起步起步左转向灯≥3 秒、鸣笛、观察后视镜、不闯动不熄火
4. 直线行驶百米直线车辆保持直线，不骑轧分道线，微调方向
5. 加减挡位操作升四挡 / 40 码逐级加减挡，不越级，不低头看挡
6. 变更车道变更车道转向灯≥3 秒 + 回头观察，一次只变一条车道
7. 靠边停车靠边停车终点项，车身距路沿 ≤30cm，不压线
8. 直行通过路口路口直行减速观察，车速低于 30km/h，路口内禁停
9. 路口左转弯左转左转向灯≥3 秒，按导向箭头，二挡及以下
10. 路口右转弯右转右转向灯≥3 秒，注意非机动车
11. 通过人行横道线人行道（常无语音）主动点刹，需自行观察
12. 通过学校区域学校区域减速至 30km/h 以下，禁止鸣笛
13. 通过公共汽车站公交站台减速观察，点刹
14. 会车会车减速靠右，保持车距，不压非机动车道线
15. 超车超越前方车辆只能左侧超车，完成后驶回原车道
16. 掉头掉头左转向灯全程常亮，禁止压路边线

⚠ 但 C1 和 C2 不一样：16 项 vs 15 项

上面 16 项是小型汽车（C1 手动挡）的考核内容。小型自动挡汽车（C2）取消「加减挡位操作」——自动变速箱由电脑换挡，学员无需手动操作离合与挡位，因此这一项自然不考。

C1 手动挡 · 16 项

比 C2 多出 加减挡位操作。硬性要求：全程必须挂到四挡，车速 30~40km/h 以上并保持几秒（多地考场要求「次高挡保持 3 秒以上」）。

C2 自动挡 · 15 项

无加减挡，全程 D 挡行驶。但难点并未消失，只是转移：观察、转向灯、点刹、踏板习惯成为新的失分区。

这是一个必须做进产品的开关。车型不只影响项目数（16 / 15），还决定了难点专项的内容完全不同。 因此首页第一屏就是 C1 / C2 切换，切换后线路项目数、项目清单、难点专项三处同步变化—— 这就是原型里那个分段控件的作用。灯光模拟则两车型完全共用，不必重复做。

4 号线①② 的真实差异

两者项目集合相同、方向相同，差别在路段次序：① 的通过学校区域排在很前面（第 5 位）；② 排到靠边停车之前（第 15 位）。② 的超车也更早。这正是「跨线路混合模式」要考的重点。

考场线路关系（公开资料）

考场共 4 条线路，其中 3 号线与 4 号线路线一致（同方向），2 号线与 1 号线方向相反。所以真正需要分别记忆的「方向 + 次序」组合是 2 套，而不是 4 套——这本身就是可以讲给用户的价值点。

仍需教练确认的 4 件事： ① 1 号线与 4 号线中标注「推导」的 路口右转弯 / 路口左转弯 / 通过人行横道线 三项，在图上没有独立标注，位置是我按路线结构推的； ② 2 号线的公开实测记录里没有出现「通过学校区域」和「通过人行横道线」，需要确认这两条线上是否真的不考，还是攻略漏记； ③ 各条线的掉头次数、左右转次数是否与上表一致； ④ C2 的替代动作——2 号线实测记录里有一项「40 码」（加速到 40 后回落到 20~30），自动挡没有换挡动作，需确认它在 C2 的考核项里是并入「直线行驶」，还是单独计一项。 这四条确认完，数据即可定稿。

数据模型

// 一条线路 = 官方 16 项的一个有序排列
Route {
  id, name,            // "l1" / "苏州科技城1号线"
  cover,               // 路线图（云存储 URL）
  nodes: Node[]        // 长度恒为 16
}

Node {
  id, routeId, seq,    // seq 决定正确顺序 —— 数据驱动，改数据不改代码
  type,                // 官方 16 项枚举，见下
  source,              // 'std'|'pub'|'map'|'inf'  ← 数据核实来源，不编造
  position: {x, y},    // 路线图百分比坐标 → 地图题用
  voice,               // 语音播报文本
  tips,                // 操作要点
  pitfall              // 扣分点 / 易错
}

// 官方 16 项（公安部令第 162 号 第三十四条）
NodeType = 上车准备 | 模拟夜间灯光 | 起步 | 直线行驶
         | 加减挡位操作 | 变更车道 | 靠边停车 | 直行通过路口
         | 路口左转弯 | 路口右转弯 | 通过人行横道线
         | 通过学校区域 | 通过公共汽车站 | 会车 | 超车 | 掉头
两条设计原则：①顺序即数据——seq 是顺序的唯一事实来源，教练调顺序只改数据； ②来源可追溯——每个节点都带 source，UI 上以圆点可视化。学员看得见「哪些是已经确认的」，我们也能一眼筛出待核项。这比假装数据全对要安全得多。

06技术选型与架构

零运维起步，把精力全放在内容与交互上

前端

微信小程序原生（WXML/WXSS/JS）即可。
排序交互用 view + 点击点选（比拖拽在手机上更稳、误触更少）。
若想兼顾抖音/支付宝小程序，再用 Taro 重写，MVP 阶段不建议。

后端

微信云开发 CloudBase（强烈推荐）
· 云数据库：线路 / 题目 / 用户进度
· 云存储：路线图、语音音频
· 云函数：判分、统计
无需服务器、无需备案独立域名，个人主体也能上线。

语音播报

innerAudioContext 播放预置音频（教练录 or TTS 合成后上传云存储）。
避免实时 TTS，一是小程序端限制多，二是真实考试就是固定播报，预置音频还原度更高。

③ 明确不用办（别花冤枉钱）

不用买的原因
服务器 / 云主机云开发包了计算资源，云函数即后端。省下 600–3000 元/年。
域名云开发的调用不需要配服务器域名，也没有「域名已备案 + HTTPS」那套要求。
HTTPS 证书同上，没有自建域名就没有证书需求。
域名 ICP 备案容易搞混：域名备案 ≠ 小程序备案。你没有域名，所以只做小程序备案即可。
短信服务用微信登录拿 openid 即可，不需要手机号验证码（个人主体也拿不到手机号接口）。
ICP 经营许可证 / EDI那些是「平台型、多商户入驻、交易撮合」才要的。我们不做交易、不做入驻，不需要。

④ 关键决策：主体选「个人」还是「个体工商户 / 企业」

这个决定要在注册账号之前定，因为主体类型一旦确定，后面很多能力就锁死了。

个人主体 · 推荐用于 MVP

能做的：注册免费、无需 300 元认证、可做查询/工具/信息展示类功能。
不能做的：微信支付、获取用户手机号、加载外链 H5、直播、附近的小程序、开通流量主（广告）。
对我们的影响：几乎没有——MVP 全免费、用微信登录、不接支付、不做 UGC。
名额：同一身份证最多备案 5 个小程序。

个体工商户 · 要收费时再升级

优势：可以开通微信支付、可选的类目更宽、支持经营者本人银行卡做主体验证（不强制对公账户）。
成本：办执照有一定成本，微信认证 300 元/年。
什么时候切：当你要做「全线路付费解锁」或与驾校合作推广时。
迁移代价：小程序主体可以变更，但流程较麻烦，所以如果要收费，建议一开始就用个体工商户注册。

⑤ 服务类目怎么选（最容易卡住的一步）

为什么这步危险：类目选错会直接驳回，而且选错类目后「嵌套高门槛功能」属于违规。个人主体能选的范围很窄。 更要注意：「教育」类目对个人主体有额外门槛——「在线教育」类目需要提供个人教师资格证或与持证机构的合作证明； 「教育信息展示」类目则不支持教育视频播放、直播和课程售卖。

11载体选型：小程序 vs HTML 单页应用

能不能做？能——而且你现在这个原型本身就是
先澄清一个事实：当前的 prototype/index.html 已经是一个 HTML 单页应用—— 单文件、零依赖、零后端、手机上直接能跑。所以问题不是「能不能做」，而是 「现阶段该先用哪个载体」。我的建议是：先用 HTML 单页应用上线，验证通过后再做小程序。

一、这个产品天然适合 HTML SPA

判断条件是否符合说明
纯前端逻辑，无复杂后端符合题库是静态数据，判分是纯计算，MVP 阶段连服务器都不需要
不依赖微信原生能力符合不用支付、不用登录、不用蓝牙/扫码/手机号——这些恰好也是个人主体拿不到的
内容静态、数据量小符合4 条线路 × 16 项 + 12 组灯光题，整包不到 100KB
碎片时间高频短时使用符合「刷 5 分钟」正是网页的长处：不用装、不用找
不做 UGC符合没有发帖/评论，不需要内容审核体系
需要微信内主动触达用户不符合订阅消息推送是网页做不到的——如果你要靠推送做复访，这条会把你推回小程序

6 条中 5 条符合、1 条权衡。说明这个产品用 HTML SPA 承载是成立的。

二、两个载体的对比

维度HTML 单页应用微信小程序
上线速度当天（传文件即上线）1–3 周（备案 7–20 工作日 + 审核 1–7 天）
现金成本0 元（免备案静态托管）0 元（个人主体），但云开发上线后要转付费
迭代速度改完即生效每次都要重新提审，1–7 天

三、选 HTML SPA 的充分条件（这 6 条都满足，方案才成立）

前提条件怎么满足 / 注意什么
① 必须是 HTTPS
硬性		微信直接用 http 会拦截，没有任何商量余地。所有下面的托管方案都自带 HTTPS，不要自己折腾证书。
② 要有分发渠道
最关键		网页没有自然流量，没人会搜到你。你必须能自己把人拉过来：教练的学员群、驾校的二维码、朋友圈。这一条不成立，网页做得再好也没人用——这是整个方案里最容易被忽略、却最致命的前提。
③ 接受「非官方网页」提示微信对第三方网页会提示「非微信官方网页，请确认是否继续访问」。用户点「继续」就能进，但会掉一部分转化。这是网页在微信内的固有代价，无法彻底消除。
④ 进度本地存用 localStorage 存错题本和掌握度，免后端。代价：换手机或清缓存会丢。想跨设备同步才需要后端。
⑤ iOS 音频要手势触发iOS 禁止音频自动播放。语音播报必须先让用户点一下（比如「开始练习」按钮），否则静音。小程序里也有类似限制，但网页更严格。
⑥ 想清楚传播文案网页分享出去是光秃秃的链接，没有卡片图。标题和摘要要写得能自证价值，否则点开率远低于小程序卡片。

四、什么时候必须回到小程序（任一命中就该切）

触发条件为什么网页做不到
要做付费解锁网页收款需要接入支付渠道，且个人难以合规收款。小程序有微信支付（需个体工商户/企业主体）。
要做用户体系手机号、微信身份、跨设备进度同步，网页端都得自建后端 + 短信，成本陡增。
要靠推送拉复访「该练车了」这类主动触达，网页完全没有手段。
要靠搜索拿自然流量微信内搜「科目三」搜不到网页，但可能搜到小程序。
「非官方网页」提示伤到转化如果实测发现大量用户在提示页就流失了，说明这个载体撑不住。

六、推荐路线：先 SPA，后小程序

阶段 1 · 今天把现有原型补上 localStorage 存进度 → 传到 CloudBase 静态托管 → 拿到可分享链接
→
阶段 2 · 一周内给 3–5 个正在备考的学员用，看他们会不会连刷三天
→
阶段 3 · 验证通过后再启动小程序：注册 + 备案 + 云开发
→
阶段 4数据模型与交互逻辑 100% 复用，只是换一层壳
为什么建议这个顺序：产品最该验证的假设是「学员愿不愿意每天刷 5 分钟」——这件事跟载体无关。 而小程序路线要先付 1–3 周备案 + 1–7 天审核 + 类目被驳回的风险。 先用网页花一天把这个假设验掉，是明显更划算的顺序。验证不成立，你省下了三周和一堆资质麻烦；验证成立，小程序的钱和时间都花在确定的事情上。
一句话总结：HTML SPA 不是「退而求其次」，而是这个阶段最合理的载体。 它的短板（无推送、无自然流量、有风险提示）在 MVP 阶段都还不构成致命伤； 而它的长处（当天上线、零成本、改完即生效、跨平台）恰好是验证期最需要的。
