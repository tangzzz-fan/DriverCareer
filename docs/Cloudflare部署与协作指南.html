Cloudflare 部署与协作指南

本项目已拆成「应用外壳 + 数据文件」两分层。这份指南讲两件事：怎么用 HTTPS 部署到 Cloudflare，以及怎么让不懂代码的教练也能维护内容。

Cloudflare Pages 自动 HTTPS 内容与代码分离 PR 预览部署 零构建
想看纯操作步骤？这份文档讲的是「为什么这样部署、多人怎么协作」。 如果你只想要一份照着做的分步手册，请看仓库里的 docs/DEPLOY-CLOUDFLARE.md（含每个输入框填什么、每个报错怎么修）。

01先把目录结构认清楚

协作的前提是分工清晰——谁改哪一层，一目了然
prototype/
├── index.html          ← 应用外壳：交互逻辑与样式
│                            【开发者维护】教练不用碰
├── editor.html         ← 教练端线路校准工具
│                            【教练使用】打开就能改，不用装任何东西
└── data/
    ├── items.js        ← 16 项要点库（口径 / 口诀 / 要点 / 扣分点）
    ├── routes.js       ← 4 条线路的顺序（只写 id + 来源）
    ├── special.js      ← C1/C2 难点专项题库
    └── lights.js       ← 12 组夜间灯光题
                        【教练维护】改内容最终落到这 4 个文件
关键设计：项目定义只写一份。「掉头」的操作要点写在 items.js 里一次， 四条线路用 { id: '掉头' } 引用它。教练改一次「掉头」的要点，四条线路的速查、顺序题、错题反馈全部同步更新—— 这是避免维护地狱的核心。
依赖检查已内建：如果只拷了 index.html 而漏了 data/ 目录， 页面会直接提示「缺少 data/xxx.js」，而不是白屏。部署时整个 prototype/ 目录要一起传。

02部署到 Cloudflare Pages

HTTPS 是自动的，不用买证书、不用配

Cloudflare Pages 有两种部署方式，请选第一种：

方案 A · 连 Git 仓库 推荐
适合：要多人协作、要版本历史
  • 每次 git push 自动部署
  • 每个 PR 自动生成预览链接——教练能在手机上点开看改得对不对
  • 一键回滚到任意历史版本
  • 谁在什么时候改了什么，全程可查
方案 B · 拖拽上传
适合：只想快速上线一个版本
  • 把 prototype 文件夹拖进 Cloudflare 面板即完成
  • 最快，5 分钟上线
  • 但没有版本历史、没法协作、回滚靠手动覆盖
  • 建议只用来做第一次试水

方案 A 的具体步骤

  1. 把项目推到 GitHub 仓库（私有仓库也免费，Cloudflare Pages 支持私有仓库）
  2. 登录 dash.cloudflare.com → 左侧 Workers & Pages → Create → Pages → Connect to Git
  3. 授权 GitHub，选中这个仓库
  4. 构建配置——本项目是零构建的纯静态站，全部留空即可： 
    Framework preset       None
Build command          （留空）
Build output directory  prototype
    关于最后一项：Build output directory 要填 仓库里那个含 index.html 的目录名（本项目是 prototype）。 如果你把 index.html 和 data/ 放在仓库根目录，这里就填 /。
  5. 点 Save and Deploy，等十几秒
  6. 拿到形如 your-project.pages.dev 的地址，HTTPS 已经自动配好
HTTPS 完全不用你操心。Cloudflare Pages 给每个站点自动签发并续期证书， 包括默认的 *.pages.dev 域名和你后来绑定的自定义域名。不要自己去买证书或配 SSL—— 微信要求网页必须 HTTPS，这一点 Cloudflare 已经帮你解决了。

可选：绑定自己的域名

想用 k3.你的域名.com 这种更好记的地址，在 Pages 项目的 Custom domains 里添加即可。两点注意：

  • 如果根域名要绑到 Cloudflare，需要把域名的 NS（DNS 服务器）迁到 Cloudflare——这只是改解析服务器，不涉及域名转移，域名还在原注册商手里
  • 不绑自定义域名也完全能用，*.pages.dev 一样是 HTTPS。想省事就先别绑

03三种角色怎么分工

关键是把「改内容」和「改代码」彻底分开
🧑‍🏫 教练 / 内容负责人
只管 data/ 目录
  • 确认路线顺序
  • 改操作要点、口诀、扣分点
  • 补题库
  • 不碰 index.html
👨‍💻 开发者
只管 index.html
  • 改交互、样式、新题型
  • 维护数据格式
  • 审阅教练提交的内容改动
  • 确保 id 不被误删
👀 试用学员
只用，不改
  • 用预览链接试用
  • 反馈哪道题表述不清
  • 反馈顺序错在哪一项
为什么这样分：教练能独立改内容，不必等开发者；开发者改界面，不会误伤内容。 两边通过 id 这个「接口」对接——这是整个协作方案能成立的关键。

04教练怎么改内容（三种难度）

方式一 · 用可视化编辑页 最推荐

直接打开 你的网址/editor.html，不需要看懂代码，也不需要安装任何东西：

  • 四条线路切换，用 ↑ ↓ 调整项目先后、✕ 删除、从官方 16 项池点选添加
  • 给重复出现的项目填「区分标签」——比如 2 号线有两次右转弯，要分别标「第 1 次」「第 2 次」
  • 逐项修改「来源」标记：教练亲自确认过的项，请从「待校准」升级为「图上标注」或「实测已核」
  • 顶部实时校验：项目数对不对（C1 应为 16）、有没有重名的项

改完点右上角 导出 routes.js，把下载的文件覆盖到 prototype/data/routes.js 即可。

为什么把它放在最前面：教练不用懂 JS 语法、不用担心引号写错、也不用记「哪些 id 存在」—— 编辑页只允许他挑已定义的项目。能犯的错被工具限制住了，协作才真的跑得起来。

方式二 · 直接在 GitHub 网页上改 零安装

  1. 打开仓库里 prototype/data/routes.js
  2. 点右上角铅笔图标进入编辑
  3. 直接把 id 的顺序上下调换即可。例如把「掉头」挪到「会车」前面： 
    改之前
  { id: 'meet',   src: 'map' },
  { id: 'uturn',  src: 'map' },

改之后
  { id: 'uturn',  src: 'map' },
  { id: 'meet',   src: 'map' },
  4. 点 Commit changes，填写一句说明（例如「按教练确认，1 号线会车与掉头对调」）
  5. Cloudflare 会在十几秒内自动部署。如果是在 PR 里改的，会生成预览链接——手机点开确认，没问题再合并
教练必须知道的 3 条规矩： ① 只改顺序和文字，不要删掉 id 那一行（删了会导致页面报错）； ② 文字里用到引号请用中文「」而不是 ' 或 "，否则会破坏文件语法； ③ 每次只改一条线路、改完立刻提交——这样出问题一眼就能看出是哪次改动导致的，回滚也简单。

方式三 · 本地改完再传 熟手用

用任何文本编辑器（VS Code、Sublime）打开文件改，改完直接拖到 Cloudflare 后台覆盖，或者 git commit 后推送。适合改动量大的时候。

改完一定要自检

数据出错的后果是页面白屏或出题错乱，所以有两条最低成本的检查：

  • 先在本地双击打开 index.html，看首页能不能正常出 4 条线路（这个项目支持直接双击打开，不需要起服务器）
  • 点进改过的那条线路，看项目数对不对——C1 应为 16 项、C2 应为 15 项。数字不对就是改漏或改重了

05推荐协作流程：改动都走预览

这是 Cloudflare Pages + Git 最值钱的地方
1. 教练在 GitHub 网页上编辑 data/routes.js
        ↓
2. 选择 "Create a new branch and start a pull request"（而不是直接提交到主分支）
        ↓
3. Cloudflare 自动为这个 PR 生成一个预览链接（形如 xxx-pr-7.pages.dev）
        ↓
4. 教练/学员在手机上点开预览链接，真机验证顺序对不对
        ↓
5. 确认无误 → 合并 PR → 正式站点自动更新
   发现不对 → 在 PR 里继续改，或用一键回滚
为什么值得走这一套：路线顺序一旦改错，学员会照着练错、考挂、然后永久流失—— 代价远高于多点两次「创建 PR」。预览链接让「教练确认」这个动作发生在真机上，而不是等到上线后。
不要做的事：不要直接在主分支上改数据然后提交，尤其不要一次改多条线路。 Pages 虽然支持回滚，但「上线了几分钟又回滚」这个窗口里，正好打开的学员看到的就是错数据。

06上线后的维护清单

事项怎么处理
改文案 / 要点改 data/items.js，一次生效到所有线路。走预览流程。
调线路顺序改 data/routes.js 里 id 的先后。走预览流程，务必让教练真机确认。
加新线路在 routes.js 数组里新增一项，no/name/seq 照现有格式写。首页会自动多出一行。
加新题型这是改代码，由开发者改 index.html。数据格式在文件头注释里。
回滚Cloudflare 项目 → Deployments → 找到上一个正常版本 → Rollback。秒级生效。
看访问量Cloudflare 自带 Web Analytics，免费，在项目面板里开启即可（无需埋点代码）。

已知的取舍（提前知道，免得踩了才后悔）

取舍说明
进度只存在本机用 localStorage 存车型选择和错题本。换手机、清缓存、换浏览器都会丢。要跨设备同步就得接后端——这属于「验证通过后再做」的事。
Cloudflare 国内访问有波动官方免费版没有大陆节点，实测多在 150–300ms，偶尔更慢。如果实测发现学员普遍打不开或加载慢，建议换到腾讯云 CloudBase 静态托管——免费额度够用、国内 CDN 极快、免备案，而且后续转小程序时环境不用搬。
微信内会有「非官方网页」提示用户点「继续访问」即可进入，但会掉一部分转化。这是所有第三方网页在微信内的固有代价，无法彻底消除。
外部依赖为零是刻意的整站不引任何第三方 CDN、字体、统计脚本。好处：不会被墙、加载快、不会因为第三方挂掉而白屏；代价：不能随手加个图表库。

07现在可以做的事（按顺序）

#动作产出
1把 prototype/ 推到 GitHub 仓库有了版本管理的源头
2Cloudflare Pages 连接该仓库，输出目录填 prototype几分钟内拿到 HTTPS 链接
3把链接发到教练的学员群，找 3–5 个人试用真实验证
4让教练按《教练校准清单》过一遍 4 条线路的顺序数据从「待校准」变成「已确认」
5走一次 PR 预览流程，让教练真机确认协作流程跑通，之后他自己就能改
第 2 步做完就已经可以给人用了。不用等数据全部校准完—— 现在的数据里，2 号线是公开实测核实的，其余线路标了「待教练校准」，速查页会用橙色圆点标出来。 先把能用的部分用起来，边用边校准，比憋一个完美版本更划算。
